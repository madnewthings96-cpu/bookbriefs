# Ta7leel: technical SEO audit and growth plan

Audit date: 7 September 2026. Implementation is local; production has not been deployed from this task. Existing redesign work was preserved. No ranking or traffic forecasts are asserted without Search Console evidence.

## What the evidence shows

The canonical production host is `https://www.ta7leel.pro`: the apex returned a 301 to www during this audit. The live homepage returned 200. A deliberately nonexistent path (`/seo-audit-nonexistent-20260907/`) returned 200 with the same ETag and content length as the homepage, confirming the catch-all response problem.

The build catalog has **87 books across 12 category values**, but only five curated category hubs. The application reads books from Firestore and sometimes replaces their summaries with `translations/bookSummaries.ts`; the build previously used only the local catalog. Live Firestore inventory and publication status were not queried, so 87 is a repository count, not a verified live total.

The article catalog contains **23 existing articles**, with full content available for every record. Their individual URLs were absent from prerendering and sitemaps. Article navigation used buttons rather than links. Book/category prerenders arbitrarily limited discovery lists to 36/24 books.

The book reader and global language provider are English-only. Arabic slugs were incorrectly treated as proof of Arabic content. Existing Arabic articles and localized category/tool introductions do exist. The `/ar/book-summaries` library itself uses the English interface. No French, Arabic or English query-string language switch exists to support the template’s old hreflang declarations.

## Fixes implemented

| Problem | Change | Practical effect |
|---|---|---|
| Articles unavailable before JavaScript | Extracted existing article data into a shared module; generated article/index HTML, metadata, Article schema and sitemap entries | Crawlers and readers without JavaScript can access the existing editorial text |
| Book content reduced to 700 characters | Public book prerenders use the existing Markdown renderer and the reader’s local content overrides | Build HTML includes the actual available summary, not just an excerpt; premium entries retain an excerpt |
| Homepage has an empty root | Added a lightweight HTML fallback using the existing headline, introduction and discovery destinations | Initial HTML exposes the site purpose and entry links |
| Poor crawl paths | Full catalog links in static library/category lists; visible category-guide links in the library; article buttons become styled anchors | Every local catalog book and article is discoverable through HTML links |
| Duplicate library pages | `/book-summaries` and the unlocalized `/ar/book-summaries` consolidate to `/summaries/` | One canonical English library; existing book slugs remain stable |
| Misleading Arabic metadata | English book metadata reflects the actual reader; removed invented template language alternates and location tags | No unsupported promise of an Arabic translation |
| Fabricated freshness | Removed deployment-date lastmod from books, hubs and sitemap index; article entries use their stored publication dates | Deploying CSS no longer claims every book was updated |
| Wrong language sitemap partition | Book pages are in the English sitemap; articles are partitioned by their content metadata | Arabic slugs no longer decide content language |
| Stale structured data after navigation | Build schemas are marked and removed as the client takes over; current article schema renders with the selected article | Previous page schemas do not survive navigation |
| Malformed asset URLs | URL resolution preserves absolute remote images and encodes Arabic paths once | Book image schema no longer concatenates two domains |
| Missing social image | Use the existing brand PNG instead of nonexistent `og-default.jpg` | Default social metadata resolves to a real asset |
| Unknown routes look successful | Netlify 404 fallback plus a React not-found page; unknown categories/articles no longer fall back to valid content | Unknown general/category/article routes can return actual 404s after deployment |
| Account URLs indexable; robots groups inconsistent | Static account noindex pages and client protection; one robots group allows crawlers to read noindex and PDF headers | Account pages stay out of search without hiding their exclusion signals |
| SearchAction destination ignored | Library reads `?search=`, handles URL changes, and searches Arabic slug words too | Shared search URLs work; search URL results are noindexed |

These choices follow Google's guidance on [JavaScript rendering and crawlable links](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics), [canonical sitemap URLs and accurate lastmod](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap), and [real, reciprocal language alternatives](https://developers.google.com/search/docs/specialty/international/localized-versions). Routing relies on Netlify's [file shadowing and redirect order](https://docs.netlify.com/manage/routing/redirects/redirect-options/).

## Remaining engineering priorities

1. **Unify publication data.** Make one published-content manifest feed the reader, build, sitemap and redirects. Reconcile all 87 local records with Firestore and local summary overrides first. A published record needs an ID, stable URL, actual content language, publication state, review status, author/editor identity and real modification date. Publishing must trigger a new build, or use server rendering. Do not manufacture dates during library sync.
2. **Finish server rendering.** Current prerenders are static fallbacks replaced by `createRoot`, not hydrated versions of the redesign. The app can briefly replace visible HTML with loading UI and still depends on Firebase. Homepage fallback is a subset of the live layout. About/news/legal routes still use the generic app entry. A shared SSR/SSG implementation should render the same components and data, preserving the redesign.
3. **Dynamic summary status codes.** `/summary/*` deliberately keeps SPA handling because Firestore can contain valid books not in the local manifest. Missing books get client noindex when the catalog loads successfully, but still return HTTP 200. Do not turn this entire namespace into 404s until publication inventory is unified; then return 404/410 from the server for verified missing/removed books.
4. **Arabic product support.** Add an actual Arabic reader and navigation, reviewed Arabic summary fields, RTL typography, and explicit locale URLs. Preserve existing indexed book URLs as English pages; launch reviewed translations under a consistent new Arabic namespace, such as `/ar/summary/<stable-slug>/`, only once implemented. Add reciprocal hreflang only to equivalent published pages. Keep Arabic category/tool pages honest about English destination content during the transition.
5. **Editorial structure.** Introduce author pages only with verified biographies, relevant books and useful reading guidance. Build topic pages only where enough reviewed material exists. Extend the five category hubs deliberately; seven remaining catalog category values should not become empty or automatic doorway pages.
6. **Mobile performance.** Measure LCP, INP and CLS on homepage, library, a long summary and an Arabic article. Inspect the many global font families, Firebase startup, full-catalog downloads, long article bundle and cover dimensions. No Core Web Vitals score was measured in this task. Avoid claiming performance improvement from prerendering alone.

## Content and information architecture

Primary navigation should lead to the library, topics, authors and articles once those destinations have real content. The library should support book-title, Arabic-title alias, author and topic search, with useful empty states. Filters are for discovery; selected curated topic hubs are for indexing. Do not index every search/filter combination.

Use one main page per intent, linked from its parent hub. Each summary should include the book and author, reader suitability, a clear original summary, key concepts, applications, limitations, related books and an editorial byline. Distinguish book opinions from facts. Verify quotations against the source edition. Investing/trading content needs reliable sources, review dates and careful treatment of risk; remove unsupported certainty and return claims during review.

| Editorial cluster | Initial Arabic intents to validate | Content path |
|---|---|---|
| Habits and productivity | ملخص كتاب العادات الذرية، بناء العادات، التسويف | Reviewed book summary → habit-building guide → related summaries |
| Money and investing | ملخص سيكولوجية المال، ملخص المستثمر الذكي، كتب الثقافة المالية | Finance hub → summary → sourced concept explainer |
| Psychology and decisions | ملخص التفكير السريع والبطيء، التحيزات المعرفية | Psychology hub → summary → decision-making article |
| Business and leadership | كتب ريادة الأعمال، ملخصات كتب الإدارة | Business hub → summaries → reading sequences by reader goal |
| Trading psychology | ملخص التداول في المنطقة، الانضباط في التداول | Existing Arabic articles → reviewed summary → related articles |

These are intent hypotheses, not measured keyword volumes. Check Search Console queries and current search results before choosing the final titles. Avoid country-specific clones; serve broadly useful Arabic, with regional examples only where they add substantive value. English pages should target their own English intent and remain useful independently.

## Execution sequence and measurement

**First 30 days:** deploy and verify this patch; reconcile catalog; establish Search Console baselines by country, language, page type and brand/nonbrand queries; inspect representative URLs; choose the first Arabic translation cluster using actual impressions and editorial capacity.

**Days 31–60:** publish a small reviewed Arabic cluster with complete summaries, related articles and one substantial topic hub; connect every page with descriptive links; add verifiable editorial attribution and source references. Build author pages only when their content is ready.

**Days 61–90:** expand the cluster that earns useful impressions and engaged reading; improve weak snippets and thin pages; address measured mobile bottlenecks; earn relevant mentions through useful original guides, partnerships and editorial outreach rather than purchased links.

Track: eligible indexed pages, canonical exclusions, soft 404s, nonbrand clicks, query/page CTR, engaged reading, search usage and zero-result queries, summary-to-summary navigation, and mobile Core Web Vitals. Segment Arabic markets (for example Saudi Arabia, Egypt, Morocco and UAE) by observed demand, not assumed traffic. Rankings and page-one placement cannot be guaranteed.

## Verification results

- Final production build passed, generating 140 route HTML files plus `404.html`; six SEO regression tests now run as part of the build.
- All 62 application/SEO Node tests passed after the build. Firestore emulator tests were not run; no database rules were changed.
- `git diff --check` passed.
- Verified the extracted article data against the original tracked source: all article records and body text were moved unchanged.
- Full TypeScript checking reports 15 errors in untouched files: missing command/dialog UI dependencies and types, catalog category/translation typing, and PDF `R2L` options. The production bundler passes, but the repository-wide typecheck is not clean.
- No Netlify preview deployment, browser/mobile visual QA, Search Console access, or field performance measurement was performed. Production redirect/status verification remains a deployment acceptance step.
